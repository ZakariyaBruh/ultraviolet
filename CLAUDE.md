# Project guidelines

- Use EasyUI (easyui.site) components everywhere. All 131 are installed in `src/components/ui`; there is no demo view, so use them in the real app. Add more with `npx shadcn@latest add Surajmaurya1/easyui/<slug> -y`.
- Read `PRODUCT.md` (who and why) and `DESIGN.md` (the look) before any UI change. The look is a broadcast station: blue-black ground, one yellow, ice data, Hanken + Barlow Condensed + Unbounded, test-card bars, ASCII torus, contour field. Retro against futuristic. Avoid monospace body text, dot-matrix and pixel type and a single red-orange accent (that is another brand's look). No pixel-art or shard decoration: it was tried and removed. No glass, blur, gradients or glow in the app.
- Surfaces: `.glass` is the floating layer (dial, player, timer), `.material` is content. Flat, ruled, small radius. Full spectrum lives only in the colour-bar strip and the landing colour-bar strip. Themes live in `lib/themes.ts` plus `html[data-theme]` blocks in `index.css`; use tokens (`bg-ground`, `text-ink`, `bg-signal`, `text-on-signal`), never hex, in app code.
- No scroll guard. The site simply never scrolls; navigation is the tab deck (`NavDeck.tsx`) and routes (`lib/route.ts`). The measured unit is a drift: leaving the tab during a session.
- The app is a no-vertical-scroll, single-screen experience at every normal window size. Page lists (`useGridFit` + `SlidePagination`) or use tabs/slides instead of scrolling. Mobile hit targets are at least 44px (`button.h-11` etc. keep a `min-height` in `index.css` so a short container cannot squash them). Small windows are the exception, in this order: `FitView` scales a screen down a little (never below 80%), and past that `Shell` measures the page (`page.scrollHeight` against its height, with hysteresis so a panel being held does not trip it) and sets `data-scroll` on `#canvas`, which then scrolls inside itself between the header and the nav (`top: var(--pt); bottom: var(--pb)`), so nothing runs underneath them; on touch the panels there use `touch-action: pan-y`. Containers that hold fixed-size controls must not shrink them: drop `min-h-0` (or give a floor) so the overflow bubbles up to that scroll instead of making siblings collide. Text that does not fit its own box scrolls inside it: use `.scroll-y` (thin bar, `overscroll-behavior: contain`) and, if it sits in a draggable panel, `data-no-drag`; `FitText` shrinks to its minimum font and then scrolls (`floor` gives the main lesson passages a minimum box height). Settings is four tabs (Settings, Look, Data, Help) so that each fits an iPad at normal text size; before that it was squeezed to about 60% by `FitView`. A hidden table for screen readers goes in a clipped `div.sr-only`, never `table.sr-only` (a table ignores the clip and widens the page). Check a change with a sweep: every route at 320x568, 568x320, 700x480, 900x600, 1024x600, 1180x500 and the normal sizes, looking for text over text, text outside the viewport, clipped text and an unexpected `data-scroll`.
- Themes differ in structure, not just colour (phosphor CRT frames, blueprint grid and dashed frames, sunset pills and sun, paper manga); Settings has accent and background pickers (`settings.accent`, `settings.bg`, applied in `lib/theme.ts`).
- Locked in, the speed warp runs at full strength behind the app and panels turn part-transparent (`html[data-locked]`) so the rush of stars shows through; no blur.
- Time counts only while locked in: `engine.ts` ticks only for a running session whose tab is visible and focused, and never credits a long gap.
- Widgets (`components/app/widgets/`, the `widgets` key in the store so it is erased with everything else): study windows that float over the Focus screen, opened from the Widgets button next to the page title (a Sheet in `App.tsx` driven by `useUI.widgetsOpen`) or from the command palette. Six of them, listed in `defs.tsx`: Notepad (saved as you type, `NOTE_MAX` characters; Copy, Save as .txt, a Clear that asks twice), Calculator (four functions worked out left to right, keys and keyboard, never `eval`), To-do list (`TODO_MAX` items), Timer (a countdown and a stopwatch kept in a zustand store outside the window, so it keeps running when the window is closed or the screen changes and rings and shows a notice wherever you are), Converter (length, mass, volume, speed, time, temperature) and Scratch board (a canvas; Save gives a PNG, the drawing itself is not stored). Each window is a `Glass` with `data-movable="widget-<id>"`, so it is dragged like every other panel (grab the title bar or a bare edge; inputs, canvases and `data-no-drag` lists never start a drag) and comes to the front when touched; new ones cascade from the top right (full width on a phone) and the stack restarts after five. A window is kept inside the page area (the widget layer, between the header and the player and nav: `range` in `Arrange.tsx` clamps `widget-*` panels to their parent, and saved offsets are clamped again on load and resize) because one hanging below it trips the small-window scroll and is cut off there, which looked like the nav covering it; the layer is a size container (`container-type: size`) so a window sizes to the room it has (`100cqh`, as the Browser's page area does) and not to the whole screen. Add a widget by adding a body component and a line in `defs.tsx`.
- Search on Radio and TV looks at every station and every iptv-org category, not just the chip you are on. Screen changes zoom in a touch, a picked-up panel grows 3%, and a drift gives the screen a small zoom ripple.
- Every panel carries `data-movable` and is always draggable: grab it anywhere that is not a control, throw it, it leans and glides (`Arrange.tsx`, offsets in `lib/layout.ts`, localStorage `friction:layout`; Alt+arrows from the keyboard). Podcasts (`/podcasts`) use the iTunes Search API plus an RSS parser in `lib/podcasts.ts`, and the EasyUI morphing blob. Paper (`html.light`) is a manga page: ink keylines, hard offset shadows, screentone, grain, Dela Gothic One.
- News (`/news`) reads the feeds in `lib/feeds.ts` through `lib/news.ts`; hidden topics are `store.mutes` (word + expiry, always with undo). Google Analytics 4 (G-CZ1GG7FPZ1) is in `index.html`, page visits only.
- Celebrations: `useUI.celebrate` shows the EasyUI rocket-party-popper card (`Celebration.tsx`) on a finished session, a finished lesson and a sharp trivia round. Loading screens use the EasyUI morphing shape loader through `LoadingBlock.tsx`. Insights has a Rings tab of donut charts.
- Learn (`/learn`) builds lessons by rules from Wikipedia text (`lib/learn.ts`; the lesson itself uses no AI): idea cards, then scored steps in rotation (fill-the-gap choice, true or false, type the missing word, estimate on a slider, put events in order, match sections to their opening lines, build the sentence from pieces), a walkable timeline, and one interactive demo after the second idea. That demo is the built-in one for the topic when there is one (`demoFor`); a topic without one gets a demo written on the fly by Gemini (see the AI demos bullet). Steps are `Step` kinds; `SCORED` kinds must be answered before Continue, each reports through `onResult(ok)` and has a Show me skip; a miss leaves a card in the review deck (`cardFor` in `LearnView.tsx`). Years are hidden in ordering items until answered (`hideYear`) and BC dates are never offered as AD years. UI for the formats is `components/app/LessonSteps.tsx`; demos are in `components/app/demos/` (`kit.tsx` frame, sliders, chips; `science.tsx`, `mind.tsx`; `index.tsx` maps a lesson title to a demo with `demoFor`: orbit, cipher, natural selection, coin law, dilemma, limiting factors, scales, double slit, dichotomy of control, herd immunity, reaction time, perspective, Roman numerals, Egyptian doubling, compounding, climate sensitivity). Demos state their simplifications in a note, never invent data, animate only what the user starts (and jump to the end under `calm()`), and keep every control at 44px. While a lesson is open the page header is hidden to give the panel room (an iPad at 1000x750 has about 430px). Plus Open Trivia DB and a Leitner review deck in `store.learn`. Panels are independent (each has its own saved offset); the player and nav keep one position everywhere and, on screens where the user never put them over something on purpose, panels are eased aside (`tidy` in `Arrange.tsx`). Deliberate overlaps are remembered in `layout.keep`. Interactive SVG inside a panel carries `data-no-drag` or the panel moves instead.
- AI demos (`api/demo.ts`, `lib/aidemo.ts`, `components/app/demos/AiDemo.tsx`): when a lesson opens on a topic with no built-in demo (built-in always wins and makes no request), `useAiDemo` asks `GET /api/demo?t=<title>`; the function (env `GEMINI_API_KEY`, optional `GEMINI_MODEL` list as `model` or `model:thinkingLevel`, default `gemini-3.5-flash-lite,gemini-3.1-flash-lite,gemini-3-flash-preview:low,gemini-3.5-flash:minimal,gemini-3.7-flash:low,gemini-3.8-flash:low`; 2.5 Flash is closed to new keys; a 429 rests a model for 30 minutes and a 503 for one; a 400 retries once without the thinking setting; the next model is started after `HEDGE_MS` (9 s) without waiting for the first to fail and the first good answer wins, within a 50 s budget; free keys allow only about 20 requests a day per model, so enable billing for steady use) pulls the Wikipedia summary for grounding, asks Gemini for TITLE/TASK/NOTE/HTML sections, and refuses code that names the network, storage, eval, the parent window, external URLs or endless loops (`parse`). Good answers are cached for a month at the edge (`s-maxage`) and in IndexedDB (`learn:demo:v1:`), so each topic is written once; limits are 10 requests an hour per IP, same-origin only (`sec-fetch-site`). Only the topic title leaves the browser; the key never does and must never be in git or the client. The demo is untrusted code: it runs in `<iframe sandbox="allow-scripts">` (no `allow-same-origin`, so an empty origin) with a CSP meta that allows only inline script and style, so nothing can read the page, its storage, or send anything out; the page reads only the words ready, touch and error from it. It is labelled AI generated and says to check it against the article. Every request carries `v=3` (the edge-cache generation, bump it when the prompt changes) and the IndexedDB key is `learn:demo:v3:`; a demo that does not work has a Not working? Write another button (`useAiDemo().again` asks once more with `n=<time>` to skip the cache). The prompt has a MAKE IT ACTUALLY WORK block (start unfinished, no degenerate defaults like a number that encrypts to itself, controls cover the whole range including zero, every control visibly changes something, no BigInt mixed with Number) because the usual failures were demos that began already solved or could not reach zero. The page calls `prefetchDemo` the moment a topic is tapped so the answer is usually back by the time the demo step comes. The demo step is a slot that is always in the lesson when `settings.aiDemos` is on (default; Settings switches it off): pending shows a loader with Continue enabled, ready shows the frame, failed (no key, error, timeout after 70 s, bad answer, a script that errors before it loads) skips the slot (`skip`, `nextAt`, `prevAt` in `LessonPlayer`) so the lesson never fails because of it. A demo that breaks after loading shows a Start it again bar. The frame is the app in small: `demos/frameStyle.ts` carries the variables (`--ink --ink2 --ink3 --ground --surface --signal --on-signal --rule --good --bad --warn --ice` and the faces `--f-body --f-cond --f-dot`) and the stylesheet (`.hud .big .fig .card .stage .meter .key .seg .primary`, flat sliders and buttons, and the per-theme changes: Paper keylines and hard shadows, Phosphor double frames, Blueprint dashed frames, Sunset pills, switched by `data-theme` on the frame's `<html>`), and `demos/frameFonts.ts` embeds Hanken, Barlow Condensed, Unbounded, Dela Gothic One and Geist Mono as data URIs (a separate chunk fetched the first time a demo is shown; the CSP allows `font-src data:`). The SYSTEM prompt in `api/demo.ts` has a THE HOUSE STYLE block (the classes, sample CSS for each theme, rules for drawing) and a worked example; keep it in step with `frameStyle.ts`, check any new example with `parse`, and remember words inside a scaled SVG shrink, so labels go in HTML. Labelling: the lesson header says `Rules, no AI` on every step the lesson builds, `Built-in demo` on a hand-written demo and `AI generated demo` (with an `AI generated` badge in the frame, and a strip under it saying it can contain mistakes and is not part of the lesson) on a written one, and the Learn header says lessons are never AI; on wide screens the text sits beside the frame so it gets the height. Test with a scratch script that calls the handler with the key in the environment, then through the lesson with `/api/demo` intercepted, at 1440x900, 1000x750 and 390x844 in both themes.
- Together (`/together`, `api/room.ts`): rooms of up to 12 by a six-character code; browsers poll (serverless cannot hold sockets) on a budget set by `delay()` in `lib/together.ts`: 3 s on the Together screen while something is changing, 6 s when it is quiet, 8 s on other screens, 12 s with the tab hidden; each poll is one round trip to Turso (`api/room.ts`, fast path in `sync`) because the free Vercel plan allows 1M function calls a month. Radio, TV and podcast episodes can be shared (an episode carries its position); a friend gets a Tune in toast because browsers may block sound they were not asked for. `vercel.json` gives `/assets/` immutable caching so returning visitors cost one request. Chat, a shared lock-in, a shared radio/TV item, and an optional Discord or Slack incoming webhook that the host sets (stored server-side only, validated to those hosts). Two names exist on purpose: the private profile name (onboarding, friends only) and the public leaderboard alias (asked on the Leaders screen). Notifications go through `lib/notify.ts` (the bell, plus system notifications when the tab is hidden); the board is watched in `lib/watch.ts`.
- All user data lives in the browser (`src/lib/store.ts` for localStorage, `src/lib/cache.ts` for IndexedDB). The only server code is `api/lb.ts` (the recommendation leaderboard) and `api/room.ts` (Together rooms), both on Turso (env `TURSO_URL`, `TURSO_TOKEN` on Vercel, never in git or the client). The score needed for the board is 0 while there is room (about 4.5 GB), and the lowest score plus one once the database is full: a newcomer who beats it replaces the lowest person. Aliases on the board are unique (folded to lowercase letters and digits, so "Zak", "zak" and "Z.a.k" are one name; a few words like "You" are reserved), and people without an alias show as "Friend XXXX". Identity is a private 32-hex key in `localStorage['friction:me']` that never leaves the browser except as a hash: the public code (`sha256(key)[:10]`, share links and recommends only) cannot act as a person, and Together uses a second secret id (`sha256('room:'+key)[:32]`, `roomId` in `lib/leaders.ts`) that no endpoint ever returns, so reading a room's member list cannot take over another account. There is no JSON import or export any more (the Data tab has only Erase everything): nothing a person can upload could ever write a key, a board row or a room seat.  `identity()` in `lib/leaders.ts` re-validates the key on every read, a room name is unique per room (`409`), and old 10-hex room ids get a "Reload the page" `426`. Erasing everything calls `eraseMe()` (`lib/leaders.ts`, `lib/erase.ts`, POST `a:'erase'` on `api/lb.ts`) which deletes the board row, pending recommends and the person's room memberships, then forgets the key; if the server is unreachable the erase is kept as a note (`friction:erase`) and `retryErase()` runs on the next board check, so a wipe is never half done. Do not add other backends. The other functions are `api/demo.ts` (lesson demos, below) and `api/feed.ts` (a News feed relay that fetches only addresses in `FEEDS`, caches 15 minutes at the edge and keeps no data), and `api/openverse.ts` (an Openverse search relay, because Openverse hangs from some countries such as Saudi Arabia; the browser asks it first and Openverse directly as a backup), none of which stores anything.
- Motion is a feature but it must answer something: respect the `motion` setting (0 calm / 1 lively / 2 lots) and `prefers-reduced-motion`. User-triggered motion settles under 300ms; exits use ease-in.
- Honest data only: never invent proof; demo history is flagged (`demo: true`) and removable. AI is only in two optional, labelled places: lesson demos and the Ask AI window (a study helper the person opens and types into). The Debrief, lessons and their questions are plain computed text and rules, never AI.

- Two dials, set apart in Settings > Look: Retro and ASCII. They do not move each other (they used to be one "era" dial). Retro, `settings.era` (100 future to 0 past, default 80, six stops of 20), sets `--retro` (stage/5), `--fx` and `html[data-retro]` 0-5 in `lib/theme.ts` (`eraStage`) and is only about the screen and its type: 0 Future (clean), 1 Afterglow (scanline, grain, warmth), 2 Broadcast (OSD, pixel kickers; the screen filters stop here, `--fx` is `min(stage, 2)/5`, so nothing past stop 2 adds a filter or a curve), 3 Arcade (Silkscreen titles, VT323 HUD lines, hard offset shadows), 4 Terminal (dashed panel outlines, a `>` prompt before page titles), 5 Full retro (square panels, heavier dashes). ASCII, `settings.ascii` (0 off to 100 a whole text world, default 20, six stops of 20), sets `html[data-ascii]` 0-5 (`asciiStage`) and is only about the 3D solids drawn in text: 0 Off (no scene, none beside titles; the timer keeps its own small turning solid and the landing keeps one), 1 Drift (one solid), 2 A few (three), 3 Floor (five and a perspective floor of text lines), 4 Stars (seven and text stars), 5 World (nine, everything moving, three beside each title). Older saves that had only `era` get `ascii` from it, so nobody's screen changes (`sanitizeData`). Body text stays in the normal face at every stop; pixel type is only for titles, kickers and HUD lines. The engine is `lib/ascii3d.ts` (point-cloud shapes torus, sphere, cube, knot, helix, pyramid; z-buffer, half-Lambert light, `RAMP`, a gamma on the light in `glyph` so the lit side, the shaded side and the edge are different characters); Resolution: the scene draws small characters on a fine grid (bold 9px glyphs on a 10px line, `FONT`/`LINE` in `AsciiScene.tsx`), grouping each row's characters into eight strength steps so a whole run is one `fillText`; `RAMP` has 17 marks ordered by measured ink; `plot` picks its point density from the solid's size in cells (`density()`) and drops back-facing points first; shaded points get a little extra for nearness, so flat faces still shade. `AsciiSolid` draws on a grid `FINE` (1.6) times finer than the box it is given and sets its text smaller by the same factor, so every call site keeps its footprint. `AsciiScene.tsx` is the canvas behind the app: the solids roam the whole screen on their own two-wave paths while they turn and breathe (`ALL`, `COUNT`, `GAIN`, `GROW`; bold 13px glyphs at 24 frames a second), it measures panels and every line of text on screen every 0.6 s and draws only 60% behind panels and 28% behind text so reading never fights it, and when the celebration card appears (`useUI.celebrate`) every solid speeds up, swings wider and swells for about five seconds before settling; `AsciiSolid.tsx` is the small `<pre>` renderer (timer, page headers via `HeadSolids` in `shared.tsx`, landing, shop; `interactive` lets a drag turn it) and the ones beside titles and on the landing sway inside their own space (`.ascii-sway`). Calm motion and `prefers-reduced-motion` draw one still frame and no sway or burst. Never add a tube, bezel, rolling bar, ticker, sprite, chromatic split or all-text pixel face: those were the clunky version and were removed (`RetroBits.tsx` and `Sprite.tsx` are gone). The pixel-art ban above still applies at Retro stops 0-1. `PhoneBreak.tsx` is the onboarding illustration (a phone in flames in front of a wheel, cable snapped, notifications flying off); export in `public/break-the-connection.png`.
- Credits, the Arcade and the Shop (`/arcade`, `src/games`, `lib/credits.ts`): `store.credits` (bal, earned, spent, best per game, log, items) is earned only by real work. Focus pays by a clean streak: 1 credit a minute, 1.5 after 10 clean minutes, 2 after 20, 3 after 35, 4 after 60 (`TIERS`/`rateAt`; a drift resets the streak, a bought Break does not; `session.credit` accrues in `tick`, the Focus dial shows the live rate and the next tier). A finished session pays +5 and +5 more if you never drifted (`finishBonus`). A finished lesson pays `lessonCredits` (3, +1 per right answer, +4 for a clean sheet), once a day per lesson; trivia pays `triviaCredits` (1 per right answer past four, +3 for a perfect round) for three rounds a day. A round costs `COST` (4) credits, or the game's own `cost` (Descent 6), and is blocked while locked in. 16 canvas games share `games/engine.ts` (480x320, keys + pointer + on-screen pad, palette read from theme tokens, 75 s cap or the game's own `round`); add one by exporting a `Game` and listing it in `games/index.ts`. Losing with time left offers one restart per round for `CONTINUE_COST` (2) credits that keeps score and time (`g.revive()`; a game opts out with `noContinue`, as the roguelite does). The Arcade shows Descent (the roguelite, `id: 'rogue'`) as a Featured banner above the grid instead of a tile among sixteen (`Featured` in `ArcadeView.tsx`). The Shop tab (`components/app/Shop.tsx`, one page per item in `components/app/shop/`; catalogue `SHOP` in `lib/credits.ts`, counts and unlocks in `credits.items`, bought through `buyItem`) sells mostly things you use: Break (25: five minutes off in the middle of a lock-in, the timer waits, leaving the tab is not a drift, recorded on the session) and Long break (45, twelve minutes), Streak shield (40: the next drift keeps your clean streak, still counted as a drift, shown as `session.shielded`), 50:50 lifelines (20 for five: remove two wrong answers in a lesson check or trivia), Time capsule (20: a note to yourself shown in the celebration after your next finished session, `sealCapsule`), Sound machine (120: rain, wind, fire, waves and hum synthesised from filtered noise in `lib/ambience.ts`, a mixer in a Sheet from the Focus screen, remembered in `items.mix`), Break kit (60: breathing guide and stretch deck on the timer during a break, `BreakKit.tsx`), Solids pack (90: pick the solid that turns in the timer), Fidget spinner (30: pointer-flick physics, a tick sound, a turn counter kept forever), Confetti cannon (12: the same card as a finished session) and the Golden Brick (5,000, does nothing, can be pressed for a thud and a counter). There is no Pause: a Break is the only way to stop the timer mid-session, it costs credits and is limited to what you have bought. Items that act on a session (breaks, shield, kit, sound machine) are used from the Focus screen; the spinner and the cannon are put away while locked in. No gambling mechanics: credits are never won in games and prices are fixed. The engine gives every game a 3-2-1 countdown, pause (P, Esc, tab hidden), particles, shake and synthesised sound (volume setting; shake and particles follow the `motion` setting and `prefers-reduced-motion`; a mute toggle is remembered in `friction:arcade-mute`). Every game must also be playable from the keyboard and, on touch, from the on-screen pad (`Game.pad`). The engine also has hit-stop (`g.freeze`), flashes, banners, shockwaves, a score multiplier chip (`g.mult`), a seeded procedural music loop that follows `g.intensity`, and `g.light/hi/lo` so shadows and highlights suit light themes. Games were pruned to the ones that earned their place (Catch, Flap, Hurdle, Aim and Whack were removed); Rally, Breakout, Snake, Invaders, Asteroids, Stack, Crossing, Orbit and Descent (a roguelite: rooms, three upgrade cards, a boss every third room) are the polished tier: new games should match that bar (layered background, telegraphed hazards, power-ups, combos, banners, hit-stop, music intensity). Smoke-test new games by bundling `games/index.ts` with esbuild (`--define:import.meta.env.DEV=false`) and stepping each `make()` with a mock `G`.
- Long passages never run into controls: wrap body text that can vary in length in `FitText` (`components/app/shared.tsx`), which shrinks the font until it fits its box (used for Learn idea cards and checks). Anything with a variable length that sits beside other things (ordering rows, match rows, a review card, a trivia question) does the same. Check lessons and demos by measuring: no element outside the panel, no `scrollHeight > clientHeight`, no overlapping siblings, at 1440x900, 1000x750 and 390x844 in the station and Paper themes.

- Music (`lib/music.ts`, `MusicControls.tsx`, the Music widget): generative, nothing downloaded. Oscillators, filtered noise, a generated reverb and echo through a compressor; four moods (Calm, Focus, Night, Retro) schedule a bar at a time four seconds ahead from a few chords and a scale (`scheduleBar` is the whole tune, shared with tests), so no session repeats. A Shop item (`automusic`, 80 credits; `MusicControls` shows a locked state with a link to the Shop until bought, and `useMusicSync` plays nothing unless owned). Off by default (`settings.music`, `musicMood`, `musicLevel`; level is multiplied by the volume setting), started from a tap (autoplay rules; `useMusicSync` waits for the first touch), quiet while the player plays or loads (`useMusic.ducked`) and back when it stops. Test by rendering each mood in an `OfflineAudioContext` (peak under 0.3, no NaN, not silent) and by wrapping `AudioContext` to read the master gain.
- Music (`/music`, `views/MusicView.tsx`, `lib/songs.ts`): real songs from three services that need no key and send CORS headers: Audius (whole tracks; trending when nothing is typed), Openverse (openly licensed music, mostly Jamendo) and the Internet Archive (each hit is looked up for its first MP3). Results from all sources are mixed. None rates its music, so the first visit shows an age gate (`settings.songAge`: -1 unchosen, 0 Everyone, 1 Teens, 2 Adults) and songs are filtered by their explicit/mature flags and a short word list (`rating`, `allowed`). Spotify and Apple previews were removed on request. A song is a `MediaItem` of kind `radio` with a `song:` id, so it plays through the one player (queue, next on `ended`, room sharing) and the made music ducks. Only typed words are sent; results are cached an hour.
- The tour (`Tour.tsx`, EasyUI `ProductTour` vendored in `components/ui/product-tour.tsx` and restyled to tokens: flat card, signal outline, 44px buttons on touch, a card that docks at the top on phones when the target is in the lower half): nine steps on the Focus screen (auto music is not in it: it is shown when bought), started once about a second after the welcome for a new visitor (`settings.toured`; a save that already had a name counts as toured, so existing users are not interrupted), skippable, re-run from Settings > Help, and it says in plain words what is rules and what is AI and where data lives. - Browser and Ask AI widgets (free, in `widgets/defs.tsx`, `large` gives the Browser a wide window). Browser (`widgets/Browser.tsx`, `api/browse.ts`, `lib/blocklist.ts`): pages are fetched by our server (never the browser), cleaned of scripts, frames, handlers and refreshes (`clean`), and shown in a `sandbox="allow-scripts"` frame with a CSP and a bridge that hands every link and GET form back to the window, so the blocklist always applies. `verdict()` refuses games (portals, stores, streamers, gaming news, `games/arcade` paths) and short-form social media (TikTok, Instagram, Snapchat, Facebook, X, Threads and the like, YouTube `/shorts`), in the window and again on the server for every address and every redirect; private networks are refused too. Full YouTube watch links open in the privacy-friendly embed (`youtubeId`), Shorts are refused. Search uses Bing (a constant in `Browser.tsx`, sent as `&e=bing`; the engine and page-script settings were removed on request, scripts are always on and the Settings rows no longer exist, and `api/browse.ts` still understands `e=google|bing|duckduckgo`); the chosen engine is asked first and the next starts if it fails or is silent for 2.5 s, the first answer wins, and the results line says which engine answered and, when it was not the one asked for, why (`engine`, `asked`, `googleOff`). Google is read only through its official Programmable Search API (env `GOOGLE_API_KEY` and `GOOGLE_CX` on Vercel, 100 free searches a day, never in git or the client) because its ordinary result page is a JavaScript challenge that a server cannot pass and getting round that is bot-check circumvention, which we do not do; until the two variables are set the Google choice answers from Bing and says so. Bing and DuckDuckGo are read from their plain result pages (honest user agent for DuckDuckGo). Results from sites that turn our server away (`WALLED` in `api/browse.ts`) are listed last. No CORS proxy is used or needed: pages are fetched by our function, not by the browser, so corsproxy.io (which refused the key offered) and its free no-key cousins are not in the path; the one free no-key relay in the app is allorigins, a News fallback. A site that answers 401, 403 or 451 is reported as `walled` (the window says it does not let other programs read its pages and offers it in the person's own browser) and is not retried through a third-party proxy, which would be sidestepping its bot protection and would send the person's browsing to that proxy. A page with under `THIN` (300) readable characters after cleaning is a shell for scripts (Khan Academy, Archive.org, OpenStax): the server flags `thin` and the window says there is nothing to show rather than showing a blank frame. The raw page may be 8 MB (most of a heavy page is scripts) and the cleaned page at most 3.3 MB, which keeps a reply under the 4.5 MB function limit. The Browser's start page is four large tiles (stacked icon over text on a phone, side by side from 640px): Wikipedia, YouTube, the engine chosen in Settings (it opens the window's own search page, a big box and a few things to try) and Add page, plus the pages the person added (`store.widgets.pages`, up to `PAGES_MAX` 8, erased with everything else; the add form refuses a blocked site; Remove pages swaps the tiles to remove buttons). The sites people most want that are script apps are answered by the window itself: an address that is a search-engine or YouTube results page (`searched`) is run as a search on the chosen engine or on YouTube, a search engine's front page (`engineHome`) and YouTube's (`ytHome`) open the window's own search pages. YouTube search (`?v=`, the `youtube` view, thumbnails from i.ytimg.com with no referrer, a result plays in the nocookie embed; Shorts and live streams are left out) uses the official Data API when `YOUTUBE_API_KEY`, or the same `GOOGLE_API_KEY` with the YouTube Data API switched on, is set (100 free searches a day) and otherwise reads the data YouTube puts in its public results page; about a third of those reads from one shared IP were turned away by YouTube's own bot check (a redirect to `google.com/sorry`), which we do not work around, so a failure says so and offers the search in the person's own browser, and good answers are cached an hour at the edge. A pasted video link plays from either start page. The sealed frame has `allow-forms` only so that a form's submit reaches the bridge (without it the browser drops Enter in a search box before any handler runs, which is why in-page searches used to do nothing); the bridge cancels every submit, turns a GET form into an address for the window, and for a POST form or one with a password field posts a notice that the window shows (`note`) because the Browser only reads pages; `form-action 'none'` in the CSP backs it up. `clean()` keeps what a page holds for browsers without scripts (`<noscript>` content, except a lone image, which is the lazy-load fallback, and a short enable-JavaScript notice), gives lazy images (`data-src`, `data-lazy-src`, `data-original`) their address, and strips the rest. A narrow frame makes some sites hide their search box until a script shows it (Wikipedia: its search icon is a plain link to its search page, so it takes one more tap). Page scripts run in the person's own browser, in the sealed frame (`sandbox="allow-scripts allow-forms"`, an empty origin, a CSP in `LIVE_CSP` that allows https scripts, styles, images and connections but no frames and no form posts), not on Vercel by default. The one exception is the cloud browser (below), which is also not a headless browser on Vercel: a headless Chromium on Fluid compute (`api/render.ts`) was built twice and removed, the second time in favour of the relay. Scripts are always on (no setting, no per-page toggle). `/api/browse?u=&s=1` returns the page with its scripts kept (`clean(..., live)` still removes frames, objects, meta refresh and CSP, and adds `<base>`). Before any page is put in the frame its address has been through `verdict()` (and again after redirects), and a page the list does not know is screened by a free chat model: `lib/screen.ts` sends only the address, title, description and the first 700 characters of text to `api/chat.ts` (mode `screen`, one word BLOCK or ALLOW, Pollinations then LLM7), remembers the answer per host for the visit, and fails open: a site that is not on the list is blocked only if the model says BLOCK, never because the model is slow or down. This is a third place AI is used (labelled in Settings and in the blocked message `checked by AI`) besides lesson demos and Ask AI; PRODUCT.md should say so. Facing issues: the frame reports how much text it has 3.5 s after it loads (`health` from the bridge) and a page under 80 characters gets an empty-page strip; the page bar has a Facing issues? button, and so does every error message. The panel offers a wrapper when `wrapFor` knows the site (YouTube, youtu.be: Friction YouTube; Google, Bing, DuckDuckGo and the like: FrictionX search; ChatGPT, Claude, Gemini, Copilot, Perplexity, Character.AI, Poe: the Ask AI window) and, always, Open in your browser (every such link, here and in the error and video views, first asks in a dialog that leaving Friction counts as drifting when locked in: Stay here or Open and drift); when there is no wrapper the latter is the only button. Add a wrapper by adding a line to `wrapFor`. A browser inside an x86 emulator (v86, called Hyperbeam in the plan) was proposed and not built: v86 is 32-bit and the only free images are tiny text-mode Linux systems, there is no modern browser for it, it would be minutes slow, the traffic would leave through a third-party relay we cannot filter (so the blocklist could not apply to a whole operating system), and a public relay can disappear. Do not add it as a stub that only looks like it works. A page's `fetch` and `XMLHttpRequest` are replaced inside the frame (`FRAME_SHIM` in `lib/frameproxy.ts`) by calls the window answers through KillCORS (`proxy.killcors.com?url=`, no key, no stated limit, slower than a paid proxy). Corsfix was used first until its free tier expired and was removed with its package; the request is made from the window's own origin, never from the frame, whose origin is empty: each address passes `verdict()` and a private-network check, no cookies go either way, the proxy is a third party that sees what pages ask for and can be slow or busy (a notice is shown). The shim also gives pages an empty cookie jar and in-memory storage. Known limits, and do not hide them: a script can move the frame by itself (`location`), which no CSP can stop, so the window counts the frame's loads and replaces the page with a notice on the second one (the target may flash for an instant); the page's own requests come from an empty origin, so only what goes through the shim works: archive.org and YouTube still show blank in the sealed frame because they need cache storage, service workers and more than it allows (the relay below runs them); pages with scripts on are not checked for being empty. With scripts off the old behaviour stays: plain page, `thin` shells get a Run its scripts button, and a tap on a control that needs a script shows a notice. Shared server code is in `api/_page.ts`. Ask AI (`widgets/Ask.tsx`, `api/chat.ts`): the relay asks Pollinations first (25 of 25 in testing), starts LLM7 after 3.5 s if there is no answer and Pollinations again at 8 s, and the first good answer wins (30 of 30 in testing, but LLM7 has a daily token limit per IP, so it is the backup). The chat lives in memory for the visit, is labelled AI generated, and nothing is stored. The corsproxy.io key offered for this was not used: it was refused outside browser requests, and a key in the client would be public.

- The cloud browser, called the relay in the code (`relay/`, its own Vercel project `friction-relay` at https://friction-relay.vercel.app, deployed with `cd relay && npx vercel deploy --prod`; the main project ignores it via `.vercelignore`): where a site opens when the sealed frame cannot run it. `CLOUD_FIRST` in `Browser.tsx` (Discord, ChatGPT, Claude, Gemini, Perplexity, Poe, Character.AI, Copilot, archive.org, Khan Academy, OpenStax) opens straight there, every error view has Open in the cloud browser as its first button, and so does the Issues panel; the relay view has a timer chip beside the address bar with the time left today (`pass.left` plus the pass in hand). It is Scramjet 1.1.0 (a service worker plus a rewriter that make a site run, with all its scripts, in the person's own browser on the relay's address) with bare-mux and the libcurl transport: the browser speaks TLS itself (libcurl.js in WebAssembly) and sends the bytes over one WebSocket to a Wisp server (`relay/api/wisp.ts`, `@mercuryworkshop/wisp-js`, an `http.Server` that answers `upgrade`; Vercel Functions serve WebSockets). So the server only moves encrypted bytes and sees host and port, not paths: the blocklist can only be applied to host names there (`hostname_blacklist` holds an object with `test()` that asks `verdict()`), ports 80 and 443 only, no UDP, no raw IPs, private and loopback refused; paths such as YouTube Shorts are refused only when typed into the Browser. Wisp's `stream_limit_*` options crash wisp-js (a bug in 0.4/0.5: `connection.streams is not iterable`), so they are not set. Earlier versions: a headless Chromium snapshot browser (removed), then Ultraviolet 2.0.0 over a Bare server (its rewriter could not run modern sites: ChatGPT's dynamic imports failed, so its buttons did nothing), and Ultraviolet 3.x with bare-mux (hung heavy pages). `scripts/prepare.mjs` copies Scramjet, bare-mux and libcurl into `relay/public/` before every build and patches libcurl-transport 1.5.2 to wait for libcurl's wasm before building its session (without it: "wasm not loaded yet"); do not move to libcurl-transport 2.x, which passes headers in a shape bare-mux 2.1.9 does not send. `go.html` order matters: create the controller and `init()` first (it creates Scramjet's storage), then register `/sw.js`, then set the transport (the Wisp URL carries the pass), then create the frame. Who may use it: the Wisp socket opens only on `/wisp/<pass>/` where the pass is `exp.hmac(RELAY_SECRET)` (`api/_relaytoken.ts`, copied into `relay/api/` by `scripts/sync-api.mjs`), minted by `api/relay.ts` for a same-origin caller, 30 minutes each, at most 4 a day per address (2 hours) and 8 hours a day in all (`RELAY_DAILY_CAP_H`; about 240 hours a month, roughly $8 at an estimated $0.035 per open-socket hour: provisioned memory plus a little CPU, bandwidth is inside the Pro allowance), so the relay cannot spend the team's $20 monthly credit by itself. The hard stop is Spend Management (`vercel budgets set --amount 1 --pause`, already set to $1 with pause on: it pauses all production projects when on-demand spend beyond the credit passes the amount; the checks run every few minutes, so keep the amount low), counted in `cloud_day` with ids starting `r` and `RELAY2` (renamed once to start fresh after testing used a day's allowance up). A pass is deliberately not tied to an IP (a phone can reach the app over IPv6 and the relay over IPv4); the limit is on minting. The time left today is shown beside the address bar (`role="timer"`). It cannot stop a script that fakes the same-origin header from minting its own 8 a day per address; Vercel BotID would. `go.html` and `wipe.html` may only be framed by Friction (`frame-ancestors`); a browser that gives no service workers to a page inside another site (Safari with cross-site tracking prevention) gets a link to open it in its own tab. The frame is `sandbox="allow-scripts allow-same-origin allow-forms allow-downloads"` (same-origin is the relay's own, a different site from Friction), no popups. A relayed page's storage (logins, cookies, caches) lives on the relay's address, so Erase everything opens `wipe.html` in a hidden frame (`wipeRelay` in `lib/erase.ts`, flagged by `friction:relay`). Tested in headless Chromium: Discord's login page (with its QR code, a WebSocket), Khan Academy (walled before), GitHub, Hacker News, archive.org's Wayback Machine, YouTube's interface (signed out, the home feed is empty; video streams are tied to the address that asked), ChatGPT's page, which then shows Cloudflare's own check ("Verifying") running in the person's browser; we do not work around bot checks, and a datacenter address may not pass. Wikipedia's article page hangs while loading here (it works in the plain frame). Edit the relay only in `relay/` and `api/_relaytoken.ts`; run `node scripts/sync-api.mjs` before deploying it.
